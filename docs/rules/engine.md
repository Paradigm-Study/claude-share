# Rules: The engine

These are among the rules that shaped the design ([AGENTS.md](../../AGENTS.md) lists every area and when to read it). Don't undo these without new evidence. Names in backticks are where to look.

- **No long-polling from the plugin.** While a plugin has a request in flight, the engine holds every prompt after the first. So each shared session reads the room through one `curl` child (`$.process.spawn`) on `stream?after=<seq>`, one JSON line per change, its address and token on stdin, never in argv. Without curl it polls, with requests that return at once. Every stream ends itself after 5 minutes and reconnects; one that ends within a minute backs off. A stream quiet for 35 s (the server sends a line every 10 s) died without a word, a Wi-Fi or VPN change: it's given up, and the row says Reconnecting at once (`STREAM_STALE_MS`).
- **One dispatch sees one moment.** Every read in a dispatch returns what its first read saw, until the dispatch writes. A look after a wait is therefore a write (`update($, atom, v => v)`, as `replaced` and `endUnheard` do), and a marker that must survive a wait is module memory (`closeMark`).
- **A hook's budget is its own time.** Past about 10 s (plain timers and `$.clock.sleep` count) the engine answers in the hook's place: in a guest's ride, that is the guest's own model answering the host's prompt. Waits that may be long go through `nap` or `pause` (a `sleep` child: the clock stops while a `$` call is in flight), never a plain promise, and every hook's `.catch` answers on the safe side (a ride ends quietly; an unanswered approval is denied).
- **No prompts from inside another hook's dispatch** (they're refused), so the plugin's prompts go out from a timer (`submitLater`, `nextGuestPromptSoon`). A plugin's own `$.command.run` skips its own command hooks, so guest transcripts are drawn by riding turns (`turn.step` answered from the room).
- **A plugin gets at most 4 MiB of an answer**: `$.http.fetch` cuts a body there without a word, and the plugin's own file read refuses anything larger. Joins and event reads ask for pages (`?max=`, `PAGE_BYTES`, `eventsSince`), and an answer that doesn't parse is a failure, never an empty one (`api`). History is read from the transcript file, newest line first, through a child (`sessionHistory`, `readBackward`), following a compacted session back into its earlier file: `session.messages` holds only what follows the last compaction.
- **Engines differ.** 2.1.295 refuses a whole tree holding a prop it doesn't know (the type scale, named gaps), so drawings return `fit(tree, modern)` (`fit.ts`), `modern` read from `AI_AGENT` on every view. From 2.1.300 a subagent's run raises `turn.start` (with `agentId`), and a prompt typed mid-turn reaches `session.append` twice (door `queue`, then as it goes in); the host's hooks skip the first of each.
- **Showing things in a guest's Claude Code happens in a turn.** A plugin's own call to a viewer outside a turn shows nothing, and auto mode refuses widgets and the browser pane; the same call yielded as a `tool` chunk of a `turn.step` opens in Desktop's viewers, so rides replay what the host's Claude showed. The Files pane (`ccd_view.show_pane`) and Claude's browser for an Open (`Claude_Browser.preview_start`, `inPane`) are called directly. The browser pane runs a local page live only inside the project folder, which is why guests save what's shown under `.shared-session/` there.
- **Auto mode gives a plugin's own calls no verdict**: its classifier reviews only calls a model turn produced. Only an allow rule lets them through, written to the settings Claude Code reads on the person's press alone, never unasked (`allowTools`): **Allow pinning** for the sidebar (`DESK_TOOLS`, retried and logged by `setPinned`) and **Allow previews in Claude** for Claude's browser. Refused there, a preview opens in the person's own browser (a shared page in the Files pane) and says so once; a ride's replay says how to open it (`refusedNote`).
- **Desktop-only things stay in Desktop.** `Svg` drawings only on the `desktop` surface; Claude Desktop's own servers (`ccd_*`, `Claude_Browser`) only when `CLAUDE_CODE_ENTRYPOINT` is `claude-desktop`. The terminal paints a collapse mark over the right end of the row above the prompt, so that row keeps 4 columns clear, and draws a call by the tool that ran, so replays draw their own rows there (`terminalName`, `replayLines`, runs grouped by `joinRun`). The Room opens with `focus`, `closeOnEscape` and `rows`, or inline in a terminal keys can't reach it.
- **How things draw.** A Fragment draws as a column Box and a Button holds only strings and Text, so rows take keyed arrays. Text that truncates beside buttons sits in a Box with `minWidth={0}`, the buttons' Box `flexShrink={0}`; titles go through `tidyTitle`. Drawings are plain images styled with `prefers-color-scheme`, never interactive art, which paints an opaque box on dark themes. What moves is a `Client` (`live.tsx`, `timeline.tsx`) ticking on the surface's clock from what the hooks hand it, drawn with the terminal's elements. A `ui.render` hook keeps the engine's own drawing (`await next(e)`, a ref a Box may hold) and adds to it.
- **One look, one row.** Each person's color comes from `look.ts` (`PEOPLE`, `colorsFor`: the host first, the same on every machine); status words take theme keys. The row above the prompt is one row whatever happens (an invite, the share question, an approval, a Pin take it over), and nothing adds a line under it. A dropped connection and its return stay out of the transcript (`lostAt`). `session.start` (a reload fires it too) redraws what the plugin drew (`$.ui.invalidate('ui.render')`), so what a row draws from lives in `$.state`.
